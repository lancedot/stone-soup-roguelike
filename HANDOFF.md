`scripts/normalize-img2-static-assets.py` currently:

- Slices floor/wall/stairs variants.
- Slices oriented wall variants.
- Slices corner wall caps from `wall_corner_variants_img2_raw.png`.
- Uses `compact_corner_cap(..., size=32)` for 32px half-grid corner caps.

`src/sprites.js` declares:

- `tile_floor` variants.
- `tile_wall_north`, `tile_wall_south`, `tile_wall_west`, `tile_wall_east`.
- `tile_wall_corner_nw/ne/sw/se`.

Note: current runtime does not actually use the generated `tile_wall_west/east` side-perspective images, because those looked wrong. Side walls are derived from the bottom wall edge rotated.

## Current Wall Rendering Logic

File:

```text
src/App.jsx
```

Key functions:

```js
Tile
wallOrientationFor
wallTileSpec
wallCornerFor
floorFillRects
```

Current idea:

- If wall cell touches open tile below: render north wall.
- If wall cell touches open tile above: render bottom/south wall, shifted down by half a tile.
- If wall cell touches open tile left/right: render bottom/south wall rotated 90 degrees.
- If a wall cell only touches an open tile diagonally and connects two real wall arms: render a 32px corner cap.
- Under wall art, render partial floor patches to fill transparent gaps without changing collision/map data.

Current `south` transform:

```js
transform: `translateY(${TILE_SIZE / 2}px)`
```

This was added because the user noted bottom walls were too high and did not align with corner caps.

## Known Visual Issue / Next Best Step

The user is still actively tuning walls. The last screenshot complaint before this handoff:

- Corner wall bricks still sometimes look absent or incomplete.
- Bottom wall height/alignment was off; the latest commit shifts bottom wall down half a tile, but this may need another visual review.

Likely next improvement if the user continues:

1. Stop treating corners as an extra full-tile wall variant.
2. Move to a real 2x2 sub-tile overlay system:
   - each 64px tile can render four 32px quadrants;
   - walls and floor are composed per quadrant;
   - collision remains unchanged at 64px grid.
3. Generate or derive clean 32x32 wall cap pieces:
   - horizontal half-wall cap;
   - vertical half-wall cap;
   - four 32x32 corner caps.
4. Render these as explicit overlays, rather than shifting full 64px wall PNGs.

This would match the user's idea: "半块砖，甚至 1/4 块砖作为最小单位来拼接".
